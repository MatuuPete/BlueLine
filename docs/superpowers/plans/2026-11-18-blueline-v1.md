# BlueLine v1 Implementation Plan

> **For agentic workers:**
> - Use superpowers:subagent-driven-development to implement this plan task by task. Steps use checkbox (`- [ ]`) syntax for tracking.
> - Each agent reads **its own task**, **Global Constraints**, the **Interfaces** blocks it consumes, and the spec sections its task cites.
> - Run every command with `corepack pnpm …`. pnpm is not on PATH; it runs through corepack.

**Goal:** a personal NBA player-props research PWA ("BlueLine"). It has:

- a board of tonight's props with hit rates, line shopping, matchup context, and rich filters
- a prop detail page with split filters
- an animated intro page
- favorites and slips
- light/dark themes

**Architecture:**

- TypeScript monorepo (pnpm workspaces + Turborepo).
- Scheduled worker jobs fetch ESPN stats and odds through adapters, store raw payloads, normalize them into Postgres, and precompute `prop_metrics`.
- The Next.js app only reads Postgres; it never calls external APIs from a request.
- Shared Zod contracts keep the UI, API, and SQL in agreement.

**Tech Stack:** Node 24, pnpm 12, Turborepo, TypeScript (strict), Next.js (latest stable, App Router), React, CSS Modules + CSS variables, Zod 4, Drizzle ORM, PostgreSQL (Neon in prod, **PGlite** in dev/test), Vitest, Testing Library, Playwright, Auth.js (next-auth v5), GitHub Actions, Vercel.

**Spec:** `docs/superpowers/specs/2026-11-18-nba-props-app-design.md`, plus the visual reference canvas https://claude.ai/artifact/HRc8K2mKCWPJaN9F28AAJT. Its artboards are Intro, Prop board, Prop detail, Phone board and Design system. Its `Main.dc.html` holds the full light/dark token set.

## Global Constraints

**Tooling:**

- Node ≥ 24, pnpm via `corepack pnpm`, TypeScript `strict: true`, ESM everywhere (`"type": "module"`).
- **Dependencies are installed once in Task 1.** Agents in Waves 1–3 must not add dependencies or edit `pnpm-lock.yaml`. If something is missing, stop and report it to the lead.

**Data rules:**

- **Jobs fetch, pages read:** code under `apps/web` never calls ESPN or odds APIs.
- **Adapters only:** only `packages/adapters` knows vendor JSON shapes.
- **Raw payloads first:** every external response is written to `raw_payloads` before it is parsed.
- **Append-only odds:** a new `prop_offers` row is inserted only when line or price changed.
- **Fixtures by default:** dev and CI use `STATS_PROVIDER=fixtures` and `ODDS_PROVIDER=fixtures`. Tests never hit the network.

**Hit-rate rules (spec §5):**

- Over hits when `stat > line`; Under hits when `stat < line`.
- `stat == line` is a push, excluded from the denominator.
- DNP and 0-minute games are excluded entirely.
- The sample size `n` is always returned with a rate.
- Windows: `l5`, `l10`, `l20`, `season`, `h2h`, `lastSeason`.

**Markets:** `PTS REB AST 3PM STL BLK TOV PRA PR PA RA STOCKS`.

**DvP:**

- Rank 1 = toughest (fewest allowed).
- Tiers: best 1–6, good 7–15, bad 16–24, worst 25–30.

**Odds math:**

- American odds; best price = highest decimal value.
- Devig = two-way multiplicative using one book's over and under.
- Consensus = mean of the no-vig probabilities across books.

**Design (spec §7):**

- **Tokens:** every color comes from the CSS variables in `packages/ui/src/tokens.css`; no hex literals in components. Both `[data-theme=light]` and `[data-theme=dark]` must work.
- **Type:** Big Shoulders (display), Archivo (UI), IBM Plex Mono (data), tabular numerals.
- **Accessibility:**
  - 44px targets
  - text contrast at least 4.5:1
  - color never the only signal
  - visible focus
  - `prefers-reduced-motion` respected
  - no violet
- **Copy:** every page shows "Research only, not betting advice. 21+. Gambling problem? Call 1-800-GAMBLER."

**Security (spec §8):**

- Every route except `/signin`, `/welcome` and `/api/health` requires a session.
- All input is parsed with `packages/contracts` Zod schemas.
- SQL only through Drizzle. Sort columns come from enum allowlists.
- No `NEXT_PUBLIC_` secrets. No export or redistribution endpoints. Sportsbooks appear as text badges, never logos.

**Git:** work on branch `build/v1`. Don't commit unless the user has approved commits; the lead reports diffs per task instead.

**Interfaces:**

- Produces:
  ```ts
  // a played-or-not game line, chronological input (oldest → newest)
  interface LogLine { gameId: string; date: string /*YYYY-MM-DD*/; season: number; oppTeamId: string; isHome: boolean;
    started: boolean; dnp: boolean; minutes: number; pts: number; reb: number; ast: number; fg3m: number; stl: number; blk: number; tov: number; }
  statValue(l: LogLine, m: Market): number
  isPlayed(l: LogLine): boolean                       // !dnp && minutes > 0
  gradeValue(v: number, line: number, side: Side): 'hit'|'miss'|'push'
  hitRate(logs: LogLine[], m: Market, line: number, side: Side): { hits: number; misses: number; pushes: number; n: number; rate: number|null }
  selectWindow(logs: LogLine[], w: Window, ctx: { oppTeamId: string; season: number }): LogLine[]   // played games only; l5/l10/l20 = last N played
  allWindows(logs, m, line, side, ctx): Record<Window, ReturnType<typeof hitRate>>
  edge(logs, m, line, side, n = 10): { avg: number|null; median: number|null; edgeAvg: number|null; edgeMedian: number|null }
  streak(logs, m, line, side): number                 // +k consecutive latest hits, −k misses, pushes skipped
  americanToDecimal(a: number): number; impliedProb(a: number): number
  devigTwoWay(over: number, under: number): { over: number; under: number }
  consensusNoVig(pairs: { over: number; under: number }[]): { over: number; under: number } | null
  bestPrice<T extends { price: number }>(offers: T[]): T | null
  dvpRank(rows: { teamId: string; allowedPerGame: number }[]): Map<string, number>   // ascending allowed → rank 1
  dvpTier(rank: number): DvpTier
  restDays(prevGameDate: string|null, gameDate: string): number|null              // same-day-after = 0 (B2B)
  splitByTeammate(logs: LogLine[], teammatePlayed: Set<string> /*gameIds teammate played*/): { with: LogLine[]; without: LogLine[] }
  parlay(legs: { price: number }[]): { decimal: number; american: number }
  jointHitRate(legs: { values: Map<string /*gameId*/, number>; line: number; side: Side }[]): { hits: number; n: number; rate: number|null }   // over shared gameIds
  gradeLeg(leg: { market: Market; line: number; side: Side }, box: LogLine|null, gameStatus: GameStatus): LegResult  // null box or dnp → 'void'; postponed/canceled → 'void'; not final → 'pending'
  ```

**ESPN endpoints:** public, no key; base `https://site.api.espn.com/apis/site/v2/sports/basketball/nba`.

|---|---|

| `/injuries` | Injury report |
| `/teams` | Teams |
| `/teams/{id}/roster` | Rosters |

### Task 6 (Data agent, after Task 5): `apps/worker` ingest jobs

**Files:**
- Create: `apps/worker/src/{cli,run-job,context}.ts`
- Create: `apps/worker/src/jobs/{schedule,boxscores,injuries,odds,budget}.ts`
- Test: `apps/worker/test/*.test.ts` (using `createTestDb`)

**Interfaces:**
- `interface JobContext { db: Db; stats: StatsProvider; odds: OddsProvider; now: Date; log: (msg: string) => void }`
- `type Job = (ctx: JobContext, opts: Record<string, string|boolean>) => Promise<{ units?: number; meta?: Record<string, unknown> }>`
- `runJob(name: string, job: Job, ctx, opts)` wraps a job:
  - writes a `jobRuns` row with status `running`, then `ok` or `error`
  - rethrows errors so the CLI exits 1
- **CLI:** `pnpm worker <ingest:schedule|ingest:boxscores|ingest:injuries|ingest:odds|precompute|grade-slips|seed> [--date YYYY-MM-DD] [--closing] [--incremental]`.
- **`seed`** runs schedule → boxscores for the last 30 fixture days → injuries → odds → precompute against fixtures. It gives dev a populated DB.

**Steps:**
- [ ] **Raw recording:** the recorder inserts into `rawPayloads`.
- [ ] **Upserts:** upserts are idempotent; running a job twice yields the same row counts. Test this.
- [ ] **Alias mapping:** odds provider player and game ids map to internal ids via `providerAliases`, matching name + team on a miss and storing the alias. Unmatched names are logged in `meta.unmatched`.
- [ ] **Append-only odds:** a second ingest with unchanged prices inserts 0 rows; a changed price inserts 1 (test). `--closing` marks rows `is_closing` for games tipping within 45 minutes.
- [ ] **Budget guard:**
  - `apiUsage` is incremented by `units`.
  - If `used + estimate > ODDS_MONTHLY_BUDGET`, markets are trimmed by `MARKET_PRIORITY` until the pull fits; if none fit, the job skips with `meta.skipped='budget'`.
  - Tests cover full, trimmed, and skipped.
- [ ] Run `corepack pnpm vitest run apps/worker`. Expected: PASS.
